# Boss Review Extension

一个给 Boss 直聘网页使用的 Chrome 扩展：同步当前页面岗位，读取岗位 JD，在人工审核后完成打招呼，并记录已沟通岗位。

它不是“自动海投器”。更准确地说，它是求职沟通的 **U 盾**：把岗位识别、详情确认、发送动作和结果记录放到一个明确的人工控制面板里，降低漏看、误发和重复沟通的概率。

## 为什么做

Boss 直聘的岗位流很快，人的注意力很容易被三个问题消耗掉：

- 岗位列表切换后，刚才看过什么、准备沟通什么，很快就乱了。
- JD 详情、地点、薪资、招聘者信息分散在页面上，人工复制成本高。
- 一旦开始批量浏览，最危险的不是慢，而是误点、重复打招呼、忘记记录。

这个项目只解决一个小问题：让你在当前 Boss 页面里，清楚地看见岗位、筛选岗位、读取 JD、确认后沟通，并留下记录。

## 功能

- 自动同步当前 Boss 页面上的岗位列表。
- 页面岗位变化后，扩展面板里的岗位随之更新。
- 点击 Boss 页面岗位时，扩展面板同步选中对应岗位。
- 点击扩展面板里的待审岗位后，读取该岗位 JD 详情。
- 列表展示岗位基本信息：岗位名、公司、薪资、地点、经验、学历、关键词。
- 支持按岗位名称和地点关键词筛选。
- 支持后台触发 Boss 默认打招呼。
- 支持开启自定义内容：默认打招呼成功后，再发送一条自定义消息。
- 记录已沟通过的岗位、发送结果和自定义内容。
- 支持导出沟通记录 JSON。
- 面板可隐藏或关闭。

## 当前边界

这个项目刻意保持小而清晰：

- 只面向 Boss 直聘网页端。
- 只处理当前页面岗位，不做跨页长期队列。
- 不承诺绕过平台限制，不做高频批量自动化。
- 不替用户判断是否应该沟通，最终动作由用户自己触发。
- 不保存云端数据，记录保存在浏览器本地扩展存储中。

如果你要把它改成批量投递器，建议先停一下。这个项目的价值不在“更快骚扰更多人”，而在“更少犯错，更清楚地沟通”。

```bash
pnpm build
```

构建产物在：

```text
.output/chrome-mv3
```

## 加载到 Chrome

1. 打开 Chrome。
2. 进入 `chrome://extensions/`。
3. 打开右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择项目里的 `.output/chrome-mv3` 目录。
6. 打开 Boss 直聘职位页面。

## 使用方式

1. 登录 Boss 直聘网页端。
2. 进入职位列表页。
3. 右侧会出现 `Boss 人审助手` 面板。
4. 面板会自动同步当前页面岗位。
5. 使用“岗位名称 / 地点”筛选目标岗位。
6. 点击岗位，读取 JD 详情。
7. 确认无误后点击“立即沟通”。
8. 如需发送自定义消息，先打开“默认打招呼后，延迟发送自定义内容”，并填写内容。
9. 使用“导出记录”保存已沟通岗位和消息记录。

## 大模型能力

代码中预留了 DeepSeek Chat Completions 调用能力：

- 默认 Base URL：`https://api.deepseek.com`
- 默认模型：`deepseek-chat`
- 只需要保存 API Key 即可调用

当前主界面已经重构为更轻的岗位扫描和人工沟通面板。如果要恢复或扩展“根据简历和 JD 自动生成打招呼语”的完整 UI，建议保持两个原则：

- 生成只作为草稿，不直接越过人工确认。
- 提示词必须要求模型不编造简历和 JD 中不存在的信息。

```text
  page/             Boss 页面适配、岗位扫描、打招呼发送
  styles/           面板样式
tests/              单元测试
```
